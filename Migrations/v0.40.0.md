# Commandments rename and installation migration

**Version:** 0.40.0
**Required package path:** `Migrations/v0.40.0.md`

This coordinated release names the authoritative guidance **Geurts Game Forge Commandments** and its independent Unity Editor brick **Geurts Game Forge Commandments Companion**. It does not migrate an open game project. Update published packages and acquire the content manually.

## Affected surface map

| Owner or surface | Current canonical name or path | Compatibility boundary |

`Documentation~` remains Unity's standard package documentation folder. Game design documents and their technique retain their subject names. Historical changelogs, frozen integration contracts and validation evidence retain their original names; they are not alternate current authorities.

## Existing installation sequence

1. Preserve any personal notes or custom instructions you need before selecting an overwrite action. Use your normal source-control workflow; the updater creates no backup or rollback.
2. In God, refresh the catalogue and update Commandments Companion through its existing package identity. Direct UPM users may update their existing Git reference to the immutable release listed in the catalogue. Do not add a second package named `com.geurts.gameforge.commandments`; that repository contains the compatibility-preserved `com.geurts.gameforge.documentation` package.
3. Update God to the coordinated release. Its old automatic-update consent does not authorize the new container. Re-enable the option explicitly only if desired after reading the new confirmation.
4. Choose **Update Geurts Game Forge Commandments**. The confirmation names `GeurtsGameForgeCommandments/` and the same three `.github` route files. It overwrites those four targets only. The old content folder, `AGENTS.md`, `Docs/GameDesign/` and every unlisted file are preserved.
5. Review each user-owned Codex guide. Either use the separate **Install Codex guide** action and knowingly replace the selected guide, or manually change only its entry path to the absolute `GeurtsGameForgeCommandments/AI_READ_FIRST.md` path, preserving your own instructions. Guides outside the project also need review. No search or bulk rewrite is performed by the updater.
6. Remove the obsolete content folder manually only after confirming that no guide, external integration or personal content still needs it. This release never deletes or merges that folder automatically. Do not load both snapshots as competing authorities.

Fresh installations use the canonical repository URLs, the retained UPM identity and the new content container. A package installation alone does not acquire Commandments content. Unsupported local/embedded sources remain outside Git release support and need deliberate reconciliation; they are never overwritten by this rename.

## Preservation and validation

No Unity asset is recreated merely to rename a label or link. Existing `.meta` GUIDs, assemblies, public compatibility APIs, module preferences and package identity remain stable. A successful-install commit signal uses a new content-target-specific key, so an old installation cannot certify the new container. Ordinary startup and restored panels remain offline.

Existing exact v1.0.0 Game Design primary-routing sections remain supported and unchanged until a separately authorized import/primary selection updates them. Do not rewrite `Docs/GameDesign/` as part of this migration.

Release evidence records compilation, Git installation/update, real exact-commit acquisition, AI routing and preservation checks separately. The live Unity project remains on its existing releases for a manual update.

## Frozen client compatibility

A frozen Game Forge Intelligence 2.0 client or schema-2 Companion cannot consume the current schema-3 archive merely by following a repository redirect. Keep its supported immutable historical documentation release until the client/package is upgraded. Never relax its schema checks or reinterpret old consent as authorization for the new folder. Historical contracts and repository tags remain available.

The Codex template keeps the `{{GEURTS_DOCUMENTATION_ENTRY_POINT}}` rendering token for installer compatibility; the generated path points to Commandments. The standard Unity `Documentation~` folder and compatibility IDs are not alternate product names.

FMOD remains optional. Its independently versioned backend is 0.1.1 at Audio release commit `8921f993be53b73f7f38ab9ec66a41335a555587`, tag `fmod-v0.1.1`. Direct Git installation uses `https://github.com/Geurtsy/com.geurts.gameforge.audio.git?path=/Integrations~/FMOD#8921f993be53b73f7f38ab9ec66a41335a555587` and requires separately licensed FMOD imports. Built-in audio stays the default.

## Owning source checkout names

For new source checkouts, use `GeurtsGameForge_Commandments` and `com.geurts.gameforge.commandments` folder names with the canonical repository URLs above. Existing local checkout directories are not automatically renamed: they may contain user changes, registered worktrees, open tools and saved project paths. Review those references and Git worktree registrations before a deliberate local directory rename, or clone the canonical repository into a new directory. Never merge or overwrite existing local content as an automatic rename step. The install sequence above applies separately to Unity consumers.
