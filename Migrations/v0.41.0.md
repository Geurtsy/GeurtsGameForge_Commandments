# Commandments ownership migration

God 0.29.0 takes ownership of the Commandments Editor service. The authoritative content remains in `Geurtsy/GeurtsGameForge_Commandments` and remains readable with ordinary Markdown tools without God.

## Source map

Implementation starts from Commandments `f4b8e99cffc6116d25b74724cf9659e3cfb2b118` (0.40.1), Companion `cf07fdffb63e61b5c151b2e42745e179f1bf7c8c` (0.14.1), God `0aade4123361066dec8b0438af453354963462a0` (0.28.1), and BigBang `9bb6b7ed718ae9febd6cf1c28f1f6d35bfefca7c` (0.2.2). Their remotes use the renamed Commandments identities. The required installed entry and manifest were read separately at version 0.36.4; that consumer snapshot is not modified. This requested ownership change supersedes the earlier independent-Companion architecture.

| Existing surface | God-owned destination or transition |
|---|---|

## Existing installations

Update God to 0.29.0 or newer and the installed Companion to adapter 0.15.0 or newer through their immutable Git releases. Either package may be updated first: an adapter with older God reports the missing supported owner, and new God with an older Companion blocks competing content operations until transition is complete. Package updates alone never acquire or replace Commandments or AI routes.

The adapter retains package ID `com.geurts.gameforge.documentation`, assembly `Geurts.GameForge.Documentation.Editor`, public integration names and the legacy window script identity. It has no updater, network transport, automatic work or menu registrations. It forwards calls to God and can be removed through Unity Package Manager when no project Editor assembly references it. Migrate code references to `Geurts.GameForge.God.Editor.CommandmentsIntegration` and God's Editor assembly first. Do not remove an assembly still referenced by custom Editor code.

God's implementation uses its own namespace and new implementation script GUIDs so even an older installed Companion cannot collide with its types or imported assets. Existing God metadata and the adapter's retained public assembly/window metadata keep their original GUIDs. No scene, prefab or user asset migration is required.

The first manual content update still shows the exact four-target confirmation. Local edits in `GeurtsGameForgeCommandments/` or its three managed AI routes must be preserved manually before approving replacement. `GeurtsGameForgeDocumentation/`, `AGENTS.md`, `Docs/GameDesign/` and every unlisted path are outside that action. Reinstall a user-selected Codex guide separately only when its existing route needs changing; package migration never overwrites it.

## Fresh setup

Install the licensed prerequisites and God, directly or through BigBang. Open God's Commandments view, check explicitly if desired, and select **Update Geurts Game Forge Commandments**. Accepting its cancel-default confirmation acquires one exact authoritative commit and replaces only the documented four targets. Companion is not required. Opening/restoring views remains offline; package installation is not content installation.

## Validation scope

Validate God alone, God plus the adapter, both update orders from Companion 0.14.1, preserved preferences/consent, single menu and updater ownership, public API forwarding, cancelled/failed/successful content acquisition, exact route bytes and unrelated-content preservation in isolated fixtures. Keep runtime assemblies, Angels, scenes and Diagnostics/logging implementation unchanged. Record final release evidence separately after these checks complete.
