# Commandments 0.44.0: Editor Appearance adoption

**Version:** 0.44.0
**Status:** Non-normative adoption note
**Required package path:** `Migrations/v0.44.0.md`

Commandments 0.44.0 adds Editor Appearance Technique 0.1.0 for workflow presentation, appropriate tabs, labelled collapsible sections, useful severity callouts and inline authoring findings. Editor UI Theme 1.5.1 retains the canonical palette, APIs, geometry and accessibility foundation. Technical 0.17.0 and Brick Contract 1.16.1 refer to both standards; technical priorities, dependencies, serialization and package lifecycle remain with their existing owners.

## Read and update explicitly

Start at `AI_READ_FIRST.md` and let the manifest select the applicable files. Supported schema-3.0.0 God Commandments consumers read the current archive's completeness list, now eleven entries including Appearance. No God or Companion package release is required solely for this content version; schema, source selection, managed directory, three route mappings and four-target cancel-default confirmation are unchanged.

Update installed Commandments manually through the existing confirmed content Update. Inspect and preserve any user-authored content inside the managed Commandments folder or three whole-file route targets before confirming replacement. The existing confirmation authorizes only those exact targets. This release adds no installer, automatic migration, extra update owner or new project mutation permission. It does not update installed packages, consumer manifests/lockfiles, Codex guides, scenes or assets. `Docs/GameDesign/` and every unlisted path remain outside the content service's authority.

## Adopt existing Editor surfaces deliberately

Review each affected Editor surface in its owning package when maintaining it. Keep the shared theme, Odin/IMGUI or UI Toolkit boundary, authored values, Unity asset GUIDs, references, Undo/prefab behavior and user-arranged window geometry. Add supported grouping, foldouts and inline findings without silently replacing working inspectors or changing serialized data. A BoxGroup alone does not make content collapsible; verify supported distinct parent/child group paths against the installed Odin version.

Routine authoring findings become inline feedback and remain discoverable in collapsed sections and inactive tabs. Genuine operation failures and exceptions retain their current Diagnostics/Unity fallback route. BigBang remains independent before prerequisites are installed and uses supported Unity/UI Toolkit equivalents; the passive Companion adapter gains no UI owner or vendor dependency.

If adoption would overwrite user-authored scripts, settings, assets or UI layouts, first describe the exact affected content and a preservation/migration procedure in that package's own guide. Do not perform that migration without the applicable user authorization. Keep the authoritative Commandments repository independent and local content readable without God.

## Acceptance boundary

This release changes documentation, completeness metadata and host validation tests only. It does not retrofit brick implementation or certify existing native Unity UI. Later implementation releases need the selected Theme and Appearance gates, appropriate focused behavior checks and actual native visual evidence. Documentation tests cannot substitute for rendering, interaction, skin/scaling, hidden-finding behavior or physical device checks. Preserve the live Unity project and let the user update installed content/packages manually.
