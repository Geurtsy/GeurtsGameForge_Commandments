# Commandments 0.45.0: integrated Forge setup

**Version:** 0.45.0
**Status:** Non-normative manual transition guide
**Required package path:** `Migrations/v0.45.0.md`

This release separates initialization, minimal bootstrap, optional diagnostics and project maintenance. Current authority remains the manifest-selected Forge Setup Technique/Contract and each technique's assigned subject. It preserves the separately published inspector Help/spacing and pooling standards.

## Help: apply the compatible set manually

1. Save intended project work and inspect changes inside the managed Commandments tree and three whole-file Copilot targets before updating their content.
2. Prepare licensed Odin Inspector and Quantum Console separately. BigBang remains an independent Editor installer and can guide this preparation before God compiles.
3. Update God to 0.34.0 and Diagnostics to 0.10.0 as a compatible pair if Diagnostics is installed. Use final immutable Git URLs from the authoritative catalogue/releases. New projects may install God through BigBang 0.5.0. Existing older God installations are preserved; API 1.1 foundation actions explain the need for an explicit God update.
4. Open Commandments in God and explicitly update to this compatible content. The schema-3 update still confirms exactly four targets before networking: the complete Commandments tree and three Copilot files. It never changes package manifests, scenes, AGENTS.md or design documents. The passive Companion 0.15.1 adapter is optional.
5. Open Build Forge and inspect local foundation separately from remote availability. Its only mandatory project setup step is minimal bootstrap: eight approved folders and SCN_BigBang/SCN_DevPlayground, first and second in effective scene lists. Full project folders, Git, guides, GDDs, FMOD and console are optional.
6. If wanted, enable Diagnostics and open Diagnostics Console Setup. Import missing TMP Essential Resources through the separate confirmed prerequisite action. Existing incomplete resources require native vendor review. Save SCN_BigBang and review its explicit implant/repair. Conflicting console/EventSystem objects are preserved and explained. Legacy God bridge and marker GUIDs/types/fields stay compatible; Diagnostics reads their references or explicitly adds its new bridge. Test console activation, input focus and shutdown before relying on it.
7. Install optional Angels 0.1.0 for project maintenance. Choose each tool separately: full create-only folders; reviewed selected asset moves; local Git inspection/init; approved create-only ignore rules; an explicitly selected existing-folder guide; selected GDD batch/primary; applicable append-only FMOD attributes. Existing artifacts remain when Angels is disabled or removed.
8. Update optional Object Pooling 0.7.2 and UI Foundations 0.12.1 for guards that skip frequent log formatting when capture is unavailable. Scene Loading 0.6.1 retains cleanup/cancellation failure details even without capture. Other optional packages keep their independently published catalogue versions.

Example: a new project installs God, acquires Commandments and creates bootstrap, then optionally installs Diagnostics for the console and Angels for project folders. No later action dispatches merely because an earlier one completed.

## Help: a fresh project

1. Create a Unity 6000.6 project and install BigBang 0.5.0 through its published immutable Git URL.
2. Check prerequisites, obtain/import the licensed Odin Inspector and Quantum Console separately, and resolve the reported Unity dependencies.
3. Explicitly fetch a supported God source, inspect its immutable revision, and install God 0.34.0. BigBang still compiles independently before these prerequisites exist.
4. Verify compilation, open God, and explicitly acquire Commandments 0.45.0 through the target-aware content interface. Confirm local foundation readiness.
5. Run the minimal bootstrap action in Build Forge when desired. Explicitly refresh the catalogue to discover optional bricks.
6. Install Angels for project maintenance and Diagnostics for capture/console when wanted. Choose each owner action separately; check the resulting project scene/profile/runtime behavior before adoption.

Opening a window or completing foundation initialization does not dispatch later actions. The old separate Commandments Companion is unnecessary; the passive compatibility adapter remains available for legacy callers and can be removed through ordinary package management after those callers are reviewed.

## Preservation and failure review

Package installation changes package sources only; it performs no automatic project migration. Save dirty or untitled scenes before actions that require saved targets. Existing startup overrides, unrelated build entries, scripts, GUIDs, input references, licensed assets and GDDs are preserved.

Forge logging uses optional Diagnostics capture without a Unity mirror or fallback. Native Unity/vendor output retains its own route. Missing or stopped capture drops ordinary Forge records; provider, startup, shutdown, input and operation failures remain visible independently in owning status/health.

Asset moves keep GUID references but cannot prove arbitrary string-loader safety. Review every row; unsafe types, special paths and uncertified Addressables state are excluded. Cancellation or failure can leave earlier completed moves; read outcomes and generate a new preview. No automatic rollback or retry is promised.

Never treat a content version or idle window as proof of compatible installed package versions. Use explicit local checks and remote source evidence. No execution capability comes from documentation/catalogue strings.
